# Architectural answers for #52 — A way to back up user data

These decisions define a deliberately small first release: create one trustworthy, portable backup from the internal writable partition to the second card. On-device restore is a separate feature because safe replacement and rollback are materially more complex than producing a recoverable copy.

## Product scope and user goal

1. **Decision:** Version 1 is a one-way, manually triggered backup only. It does not restore on-device. **Rationale:** This satisfies the issue without combining a non-destructive copy operation with destructive migration logic. **Constraint:** The format must remain usable for manual recovery and later automated restore.
2. **Decision:** Optimize for disaster recovery after reflashing/replacing the first card and for copying data to another MayonnaiOS installation. **Rationale:** Those are the cases in which a copy on the second card has value. **Constraint:** Completion means the files can be inspected and copied with ordinary desktop tools.
3. **Decision:** Back up an explicit allowlist of mutable user-data roots, not all of `/root`. **Rationale:** `/root` also holds large reproducible software and the second-card mount itself. **Constraint:** Production configuration cannot expand the operation to an arbitrary source path.
4. **Decision:** Include `/root/.config/mayonnaios`, `/root/.config/retroarch`, `/root/.config/moonlight`, and `/root/pickles`. Include all regular files and empty directories below those roots except generated RetroArch core links and `mayonnaios.cfg`. **Rationale:** This covers OS preferences, emulator settings/SRAM/save states, streaming settings, and Pickle code/state. **Constraint:** Missing roots are recorded as absent and do not fail a backup.
5. **Decision:** Exclude `/root/ROMS`, `/root/bundles`, `/root/cores`, `/root/mnt`, generated `/root/.config/retroarch/cores`, generated `/root/.config/retroarch/mayonnaios.cfg`, Bluetooth bonds, and VintageNet/WiFi persistence. **Rationale:** ROMs and executables are large or reproducible; mount points recurse into the destination; generated files are rebuilt; bonds and WiFi credentials are secret/device-specific and have no safe import contract. **Constraint:** The screen and README must state that games, installed software, WiFi credentials, and Bluetooth pairings are not included.
6. **Decision:** Maintain one named source catalog in `MayonnaiOS.Backup`; update it whenever `docs/data-layout.md` gains mutable user data. **Rationale:** Explicit ownership is safer than silently sweeping `/root`. **Constraint:** Add a documentation rule and a test asserting the catalog's logical names and exclusions.
7. **Decision:** Backups are not device-locked, but carry format version, firmware application version, and target/device profile metadata. **Rationale:** User data should be portable while incompatibility remains diagnosable. **Constraint:** A future restore must validate format compatibility and warn on target/version differences.

## On-device UX

8. **Decision:** Add a **Back up user data** app row in the System column. **Rationale:** This is a device operation, not a general file-manager verb; `MayonnaiOS.Files` intentionally refuses recursive jobs. **Constraint:** Register the row in target and host program configuration.
9. **Decision:** The idle screen says what is included/excluded, names the second card as destination, and warns not to remove it or power off while running. **Rationale:** The operation is safe only while removable FAT media stays present. **Constraint:** Fit the essential warning and action within the existing 640×480 scene conventions.
10. **Decision:** A starts a preflight and then immediately backs up; no second confirmation is needed because the operation is non-destructive to user-visible files. **Rationale:** Its private backup namespace is the only destination it may replace. **Constraint:** Existing known-good data is preserved until the new backup is complete.
11. **Decision:** Show phase, files completed/total, bytes copied/total, percentage, and current logical root. **Rationale:** A preflight scan supplies accurate totals and reassures users during large save-state copies. **Constraint:** Do not display full paths that may overflow the panel or leak secrets.
12. **Decision:** Menu cancels. Cancellation removes the current staging tree where possible and leaves the last published backup untouched. **Rationale:** Long operations need an escape path. **Constraint:** Stale staging is also cleaned on the next start, so power loss is recoverable.
13. **Decision:** The user cannot leave without cancelling. Existing launcher behavior already pauses automatic sleep while an app is active. **Rationale:** Keeping one owning screen makes lifecycle and progress unambiguous. **Constraint:** The copy worker must actually terminate when its app terminates; do not leave an unlinked orphan.
14. **Decision:** Completion reports file count, byte count, verification success, and destination. Do not depend on a timestamp. **Rationale:** Device wall-clock time may be invalid. **Constraint:** Metadata may include UTC only when `MayonnaiOS.Clock.synchronized?/0` is true.
15. **Decision:** Map no card/not mounted, read-only card, insufficient space, source-change, unsafe entry, I/O/sync/rename, cancellation, and verification errors to short actionable messages; retain the structured reason in logs/tests. **Rationale:** `inspect/1` alone is not usable on the panel. **Constraint:** Unknown errors still render without crashing.
16. **Decision:** Fully support host mode using configured scratch source and destination roots. **Rationale:** The project requires complete UI development on a laptop. **Constraint:** Host configuration must never point at real `/root` or a developer's personal files.

## Backup identity, layout, and retention

17. **Decision:** Own `/root/mnt/games/MayonnaiOS/backup-v1` on device (with configured equivalents in tests/host mode). **Rationale:** A product-named directory avoids collision with stock `ROMS/`; the `v1` names the format. **Constraint:** Never write elsewhere on the second card.
18. **Decision:** Retain one published backup, not timestamped snapshots. **Rationale:** It works without a clock, has predictable space use, and matches the issue's simple recovery goal. **Constraint:** The current backup is replaced only through staged publication.
19. **Decision:** No pruning UI is needed because there is only one published backup. **Rationale:** Retention policy would add scope without improving first-release recovery. **Constraint:** Temporary/previous directories are implementation state, not retained snapshots.
20. **Decision:** Preserve the previous backup until the staged replacement has copied and checksum-verified every file and has a complete manifest. **Rationale:** A failed run must not destroy the only recovery copy. **Constraint:** Publication uses recoverable `current`, staging, and previous directory names within the same filesystem.
21. **Decision:** Use a browsable directory tree plus a JSON manifest, not an archive. **Rationale:** It streams with bounded memory, is inspectable on any desktop, and avoids archive truncation making all files inaccessible. **Constraint:** Logical source names live below `data/`; no absolute source path appears as a destination path.
22. **Decision:** The manifest records format version, optional synchronized UTC, firmware version, device profile, each logical source, exclusions, and each file's relative path, byte size, and SHA-256. A completion marker/state is written last. **Rationale:** The manifest supports verification and future restore. **Constraint:** Generate deterministic ordering and JSON using OTP's available JSON support.
23. **Decision:** Do not use time in directory naming or ordering. Store a timestamp only when synchronized; otherwise store `null`. **Rationale:** A false 1970 timestamp is worse than an explicit unknown. **Constraint:** The single-backup model defines “latest” by publication, not clock.
24. **Decision:** Preserve regular-file bytes and empty directories. Record source size and optional mtime for information, but do not promise Unix permissions/ownership/timestamps on FAT. **Rationale:** User settings and saves depend on contents and paths, not Unix metadata. **Constraint:** Dotfiles are included within approved roots.
25. **Decision:** Reject every symlink encountered except paths explicitly excluded before traversal; never follow or reproduce links. **Rationale:** The included user-data roots should contain data, while generated RetroArch links are known exclusions; following links can escape scope or duplicate bundles. **Constraint:** An unexpected symlink fails the run rather than silently omitting user data.

## Consistency and safety

26. **Decision:** Starting the app through the launcher guarantees no external game/program is running; that is sufficient for RetroArch. Do not stop supervised headless Pickles in v1. **Rationale:** The launcher already enforces one foreground program. **Constraint:** Detect mutation per file and fail rather than publish a potentially inconsistent backup.
27. **Decision:** Call `MayonnaiOS.Saves.flush/1` only through the launcher's existing confirmed-program-exit path; the backup itself must not fsync live source files. **Rationale:** `Saves` explicitly warns that flushing while RetroArch runs can preserve a truncation. **Constraint:** Backup begins only as a launcher app, after any prior program has been reaped.
28. **Decision:** Require each source regular file's type, size, and mtime to match the preflight record immediately before and after streaming; fail the whole run if they differ. **Rationale:** Filesystem snapshots are unavailable, but publication of known-changing input is avoidable. **Constraint:** Document that this is a verified per-file copy, not an atomic snapshot of all roots.
29. **Decision:** Write each file to a sibling `.part`, SHA-256 while streaming, sync the open destination handle, close, rename, re-read and SHA-256 the published staging file, then write/sync/rename the manifest last. **Rationale:** This extends the proven `MayonnaiOS.Files` durability shape and detects destination corruption. **Constraint:** A backup is valid only when its final manifest says complete and all hashes match.
30. **Decision:** Claim verified file contents and recoverable publication, not power-loss atomicity. **Rationale:** OTP cannot fsync directories and FAT/exFAT is not journaled. **Constraint:** UI/docs must still instruct safe unmount before card removal and warn against interruption.
31. **Decision:** At start, remove only the private staging directory; inspect publication state and recover a valid `previous` backup if `current` is absent or invalid. Never delete the sole valid copy. **Rationale:** Power can fail between publication renames. **Constraint:** Recovery logic is deterministic and covered for every current/staging/previous combination.
32. **Decision:** SHA-256 verify every destination file and store hashes in the manifest. **Rationale:** A backup exists specifically to be trusted later, and the extra read is acceptable for settings/saves while ROMs are excluded. **Constraint:** Verification failure prevents publication.
33. **Decision:** Overwrite only files inside a newly created private staging tree and rotate only the feature's own `current`/`previous` directories. Refuse unexpected non-directory entries at those names. **Rationale:** This preserves the project's “never overwrite user files” policy outside the owned namespace. **Constraint:** No generic recursive delete accepts caller-supplied paths.
34. **Decision:** Preflight sums regular-file sizes and requires that amount plus 5%, manifest allowance, and the size of the current backup until rotation completes. **Rationale:** The previous backup remains during staging. **Constraint:** If exact current-backup size cannot be measured safely, fail closed rather than delete it early.
35. **Decision:** Any missing/unmounted/read-only destination or I/O failure aborts, cleans staging best-effort, and preserves current. **Rationale:** Continuing after removable-media failure cannot yield a trustworthy backup. **Constraint:** Re-check that the destination resolves to the configured games-card mount before publication.
36. **Decision:** Add lightweight ownership coordination to `MayonnaiOS.GamesCard`: unmount returns `{:error, :busy}` while a backup lease is held, and the worker releases the lease in `after`. **Rationale:** Open files alone do not protect rename/publication boundaries. **Constraint:** A crashed owner is monitored so the lease cannot remain stuck.
37. **Decision:** Do not include WiFi credentials or Bluetooth bonds in v1 and do not add encryption/passphrase UX. **Rationale:** The device has no practical text-entry flow for strong encryption keys, and these secrets/device identities are not required to protect game progress/settings. **Constraint:** Exclusion is explicit in UI, manifest, and docs.
38. **Decision:** Source roots are compiled/configured as logical-name plus absolute-root pairs validated at startup; destination paths are constructed only from fixed private names and validated relative components. **Rationale:** No UI or manifest input should become an arbitrary filesystem path. **Constraint:** Reject `..`, separators, NUL, invalid UTF-8, and paths whose lexical or real traversal escapes the approved source.

## Restore and compatibility

39. **Decision:** Restore selection is out of scope. **Rationale:** Version 1 has no restore operation. **Constraint:** The manifest groups files by logical source to permit future category selection.
40. **Decision:** No on-device replacement or rollback is implemented. **Rationale:** Avoid destructive behavior in this issue. **Constraint:** Future restore must stage/validate before replacing current data; this PRD must not pre-implement it.
41. **Decision:** No services are stopped/restarted for restore because restore is absent. **Rationale:** Keep the design honest. **Constraint:** README manual recovery instructs recovery while the destination system is powered down or before affected apps run.
42. **Decision:** Conflict handling is deferred to a restore design. Manual recovery must instruct users to retain their current data before copying. **Rationale:** Silent replacement is inconsistent with project policy. **Constraint:** Do not label raw file copying as a safe merge.
43. **Decision:** Record `format_version: 1`, firmware version, and device profile now; future restore rejects unknown format versions and warns on firmware/target differences. **Rationale:** Compatibility data is cheap at creation and impossible to reconstruct later. **Constraint:** A backup remains desktop-readable regardless.
44. **Decision:** WiFi and bonds are excluded, so cross-device identity conflicts do not arise. **Rationale:** This is the safest portable default. **Constraint:** Adding either later requires a separate export/import and security design.
45. **Decision:** Document manual recovery: safely unmount/power down, read `manifest.json`, verify hashes with common desktop tools or the supplied checksum list, and copy selected `data/<logical-root>` contents back to their documented paths. **Rationale:** A backup without a recovery procedure is incomplete. **Constraint:** State clearly that manual replacement should preserve existing files first and may require a reboot.

## Architecture and operation

46. **Decision:** Create `MayonnaiOS.Backup` as the filesystem/domain boundary, `MayonnaiOS.Backup.App` as the state machine, and `MayonnaiOS.Scene.Backup` as rendering. Do not extend `MayonnaiOS.Files`. **Rationale:** `Files` explicitly rejects recursive long-running copies; the Update app supplies the established async-app pattern. **Constraint:** Reuse concepts, not private functions, unless a small generic streaming helper can be extracted without weakening `Files` contracts.
47. **Decision:** Run preflight/copy/verification in one monitored, linked worker owned by the temporary app process; allow exactly one job through the registered app and games-card lease. **Rationale:** Scenic remains responsive and concurrency is unambiguous. **Constraint:** Cancellation/termination kills the worker and executes best-effort cleanup/release.
48. **Decision:** The app receives throttled progress messages from the worker, stores a snapshot, and notifies monitored scene watchers, matching `Update.App`. **Rationale:** This is the project's existing app protocol. **Constraint:** Coalesce updates to a few per second so many small files cannot flood the mailbox.
49. **Decision:** Configure a fixed source catalog and destination root, with test-only injectable filesystem/hash/sync/clock seams passed as options. Chunk size stays a module constant. **Rationale:** Tests need failure injection; production must not gain arbitrary path knobs through UI. **Constraint:** Host config explicitly supplies scratch roots.
50. **Decision:** Log start, final summary, cancellation, recovery actions, and structured failures; do not log file contents or a line for every successful file. **Rationale:** RingLogger is bounded and paths can reveal private names. **Constraint:** The panel gets sanitized logical-root/current-relative context only.
51. **Decision:** Make desktop portability an acceptance requirement and add a README section for location, contents/exclusions, manifest verification, safe unmount, and manual recovery. **Rationale:** There is no v1 on-device restore. **Constraint:** Use ordinary directory/JSON/SHA-256 conventions, not Erlang-only serialization.

## Verification and acceptance

52. **Decision:** Support at least 100,000 files and data up to available card capacity with bounded memory: one 64 KiB copy buffer, one file record at a time, and manifest metadata accumulated or streamed without loading file contents. No throughput promise until hardware measurement. **Rationale:** Save states can be large and Pickle trees numerous, but RAM is only 1 GB. **Constraint:** Tests assert bounded streaming behavior; hardware notes record observed throughput.
53. **Decision:** Host tests must cover catalog inclusion/exclusion, missing roots, hidden/empty entries, unsafe names, symlinks, deterministic manifest/hashes, low space, current-backup space accounting, cancellation, mutation, stale-state recovery, card lease, and injected open/read/write/sync/rename/hash failures. **Rationale:** Most safety guarantees are ordering/error-path guarantees. **Constraint:** Tests use temporary directories and injected seams, never mounts or `/root`.
54. **Decision:** Instrument sync/hash/rename operations in tests and assert exact ordering: copy → destination sync → per-file rename → destination re-hash; all files verified → manifest sync/rename → backup publication. **Rationale:** Looking at final files cannot prove durability ordering. **Constraint:** No completion marker or `current` publication occurs on any earlier failure.
55. **Decision:** Manually validate exFAT and vFAT, absent/full/read-only cards, physical removal and power loss during copy/publication, large save states, unusual valid filenames, recovery on next run, and safe unmount. **Rationale:** Host filesystems cannot model removable FAT failure semantics. **Constraint:** Add a documented hardware checklist; do not claim power-loss behavior beyond observed results.
56. **Decision:** #52 is accepted when a user can use only gamepad controls to create a checksum-verified backup on the second card; progress and actionable failures are visible; interruption leaves the prior backup recoverable; and README instructions can recover included settings/saves manually. **Rationale:** This is a complete, testable first increment. **Constraint:** Keep restore, encryption, snapshot history, ROM backup, WiFi, and bonds outside this implementation.
