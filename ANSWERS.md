# Architectural answers for #42

## Product scope

1. **Decision:** The issue ships directory Copy and cross-filesystem directory Move together. Same-filesystem Move remains a direct rename. **Rationale:** Both missing behaviors depend on the same recursive engine, while preserving rename keeps the fast atomic path. **Constraint:** A directory move may enter recursive mode only after rename returns `:exdev`.
2. **Decision:** General recursive Delete is out of scope. **Rationale:** Copy/move solves the stated card migration problem; broad destructive deletion has a different risk and confirmation design. **Constraint:** Existing Delete semantics remain unchanged, except for tightly validated cleanup of app-owned incomplete-copy staging trees.
3. **Decision:** Recursive operations support directories and regular files only. Empty directories and zero-byte files are supported. **Rationale:** That covers ROM trees without inventing semantics for devices or sockets. **Constraint:** Any symlink or special entry rejects the entire tree during preflight.
4. **Decision:** The operation is available under every configured Files root. **Rationale:** `MayonnaiOS.Files` is already the policy boundary, and permissions/read-only errors are honest outcomes. **Constraint:** Locations, safe names, no-overwrite, and filesystem permissions remain authoritative.
5. **Decision:** Allow one recursive operation device-wide. **Rationale:** Two card-sized transfers would contend for I/O and make free-space checks unreliable. **Constraint:** A second request is refused as busy until the first worker exits.

## User flow and controls

6. **Decision:** Offer Copy on non-symlink directory rows in the existing Y sheet. Picking it only fills the clipboard. **Rationale:** This matches file copy and makes the sheet truthful. **Constraint:** A symlink that resolves to a directory is still a link and is not copyable.
7. **Decision:** Paste immediately starts preflight; no extra confirmation is required. **Rationale:** Paste is already the committing action and preflight writes nothing. **Constraint:** The UI must label the scanning phase before any slow walk starts.
8. **Decision:** Keep browsing controls live: directions, shoulders, A for opening directories/files, B for cancellation, and Menu for root. Disable actions that launch a program/app or mutate files. **Rationale:** The launcher must remain responsive without handing the panel/input away from progress. **Constraint:** While a job exists, B is globally reserved for cancel rather than column-back.
9. **Decision:** B requests cancellation and does not also navigate. **Rationale:** A single press must have one effect, and cancellation must be discoverable. **Constraint:** The footer always says `B cancels` while cancellation is possible and `Cancelling…` after it is requested.
10. **Decision:** Menu returns to the browser root while work continues. **Rationale:** Menu retains its global “home” meaning. **Constraint:** Progress remains visible there and B still cancels.
11. **Decision:** Block launching programs/apps, sleep, and orderly power-off while recursive work is active; show a short explanation. **Rationale:** External programs take the panel/input, sleep hides progress, and power-off knowingly creates a partial tree. **Constraint:** The worker cannot disable physical power removal, so staging still makes interruption recognizable.
12. **Decision:** Disable all file mutations, clipboard replacement/forget, and second paste while active. Read-only browsing and file inspection remain available. **Rationale:** One stable source/destination and one writer make completion behavior deterministic. **Constraint:** The current clipboard is retained until terminal handling.
13. **Decision:** A successful copy keeps the clipboard; a successful move clears it only after source deletion succeeds. Cancellation or failure keeps it. **Rationale:** This preserves existing clipboard behavior and permits retry. **Constraint:** A move that copied but could not delete reports failure and retains the source and clipboard.

## Progress and feedback

14. **Decision:** Show phase, completed/total bytes, completed/total entries, and a truncated current relative path. During cleanup show directories remaining rather than bytes. **Rationale:** Bytes reflect large-ROM progress; entries make empty directories and zero-byte files visible. **Constraint:** Progress payloads remain small and contain no absolute paths.
15. **Decision:** During preflight show `Scanning <name> — <entries> entries, <bytes> found`. **Rationale:** A percentage would be false before the total is known. **Constraint:** The first scanning state is painted before the worker walks.
16. **Decision:** Count both files and directories as entries. **Rationale:** Every created object should advance observable progress. **Constraint:** Byte totals include regular-file contents only.
17. **Decision:** Emit/repaint on phase changes and completion, otherwise at most four times per second. **Rationale:** 250 ms is responsive without re-rooting Scenic per chunk. **Constraint:** The worker may update internal counters per chunk but coalesces owner messages.
18. **Decision:** Terminal results use the existing status line: success, cancelled, or the first precise failure with the relative path. They remain until normal browser activity replaces them. **Rationale:** This matches existing operation messages. **Constraint:** Logs retain full paths and detailed reasons; panel text is bounded.
19. **Decision:** On success, cancellation, or failure, refresh the focused column only if it is the destination or source parent; otherwise normal reopen refreshes it. **Rationale:** Rebuilding arbitrary open levels is complex and stale snapshots are already an accepted browser property. **Constraint:** Returning to the affected column may require close/reopen if it was not focused at completion.

## Cancellation and lifecycle

20. **Decision:** Check cancellation during preflight between every entry, during copy between every 64 KB chunk, before promoting staging, and before source deletion. **Rationale:** This bounds cancellation latency even on one huge ROM. **Constraint:** No source deletion begins after cancellation is observed.
21. **Decision:** Graceful cancellation removes the current file part and the entire app-owned staging tree, then reports cancelled. **Rationale:** A requested stop should restore the no-destination state. **Constraint:** Cleanup validates the private marker before recursive removal; if cleanup fails, preserve and report the incomplete tree.
22. **Decision:** Run the worker as a temporary child; never restart it. It monitors Launcher and cancels/cleans up if Launcher dies. **Rationale:** Replaying a filesystem mutation is unsafe. **Constraint:** Application supervision provides the worker supervisor, but job restart is `:temporary`.
23. **Decision:** Card removal or remount appears as the exact read/write/rename error, stops the job, and triggers best-effort staging cleanup. **Rationale:** Continuing after mount identity changes risks writing to the mountpoint on the wrong filesystem. **Constraint:** Before final promotion, compare the destination `df` device identity with the preflight identity when available.
24. **Decision:** Do not implement resume. Recognizable staging plus safe discard/retry is sufficient. **Rationale:** Resume requires a durable source snapshot and conflict protocol beyond this issue. **Constraint:** A verified stale stage blocks paste until explicitly discarded.

## Interrupted and partial copies

25. **Decision:** Build beside the destination as `<name>.part`, containing a private marker file that identifies it as a MayonnaiOS recursive-copy stage. **Rationale:** The suffix is visible after pulled power and the marker distinguishes app-owned staging from user data. **Constraint:** If either final name or staging name exists, do not overwrite it.
26. **Decision:** The final directory appears only after the whole staged tree is complete and every regular file has been fsynced, via same-directory rename. **Rationale:** A final-looking directory is either complete or absent. **Constraint:** Promotion must remain on the destination filesystem.
27. **Decision:** Never replace or resume an existing stage automatically. Return a dedicated incomplete-stage error. **Rationale:** Automatic replacement could delete user data and resume cannot prove source identity. **Constraint:** The UI offers discard only when the marker validates.
28. **Decision:** Expose `Discard incomplete <name>.part` in the actions sheet for a validated stage, behind the existing two-button destructive confirmation. **Rationale:** Recovery must be possible on-device without enabling general recursive delete. **Constraint:** The private cleanup API refuses trees without the exact marker.
29. **Decision:** No-overwrite applies to both final and staging names. **Rationale:** A staging collision is still somebody’s data unless proven otherwise. **Constraint:** Cleanup is an explicit separate action, never a side effect of Paste.
30. **Decision:** Fsync every completed regular-file part before its rename and fsync the marker; document that directory entries and final directory rename cannot be fsynced through OTP. **Rationale:** This preserves the strongest durability the current project can provide without claiming more. **Constraint:** Empty-directory durability remains filesystem-dependent.

## Preflight and capacity

31. **Decision:** Complete preflight before creating staging. **Rationale:** Unsupported entries and obvious ENOSPC must fail without leaving output. **Constraint:** Preflight produces a manifest and source summary but performs no writes.
32. **Decision:** Require free bytes to be at least file bytes plus `max(16 MiB, 1% of file bytes)` headroom. **Rationale:** `df` free space does not account for metadata needed by many small entries. **Constraint:** This is a conservative policy constant covered by tests, not a precise filesystem estimator.
33. **Decision:** Fail preflight with `:space_unknown` when destination free space cannot be measured. **Rationale:** A recursive operation is too large to begin without the promised up-front check. **Constraint:** Existing regular-file copy behavior remains unchanged.
34. **Decision:** Recheck free space before each regular file using its remaining bytes. **Rationale:** Concurrent writes and estimate error can invalidate preflight. **Constraint:** A mid-copy ENOSPC follows normal failure cleanup.
35. **Decision:** Keep a relative-path manifest in worker memory. **Rationale:** ROM trees are bounded enough for a compact list and this avoids extra destination writes or a second unsnapshotted traversal. **Constraint:** Manifest entries contain relative components, type, size, and source stat identity fields; no file contents.
36. **Decision:** Re-`lstat` every manifest entry immediately before use and require type, size, mtime, and inode/device (where available) to match preflight. **Rationale:** Changed sources must fail rather than silently produce a mixed snapshot. **Constraint:** Any added/removed entry discovered by a final source verification fails the operation before promotion/source deletion.

## Symlinks, entry types, and path safety

37. **Decision:** Any symlink anywhere rejects the entire operation during preflight. **Rationale:** This exactly extends the existing refusal of symlink copy sources. **Constraint:** Do not follow links while walking; use `lstat`.
38. **Decision:** Do not copy links as links. **Rationale:** Link targets and portability across cards add policy not needed for ROM migration. **Constraint:** Error wording names the offending relative path.
39. **Decision:** Reject sockets, devices, FIFOs, and every other unsupported type during preflight. **Rationale:** Skipping would produce a destination falsely presented as complete. **Constraint:** No staging is created after such a failure.
40. **Decision:** Pass every descendant component through `safe_name/1`; an existing over-policy name makes the tree unsupported. **Rationale:** Recursive operations must not bypass the same path boundary as interactive navigation. **Constraint:** The scan reports the first rejected relative component.
41. **Decision:** Re-`lstat` immediately before opening each source and open only regular files. **Rationale:** This narrows the change-to-symlink race and avoids following a preflight-approved path after replacement. **Constraint:** A mismatch aborts rather than retries.
42. **Decision:** Explicitly reject destination inside source and source inside destination using canonical resolved root paths plus component-boundary checks. **Rationale:** Overlapping configured roots can otherwise recurse into staging or delete their own destination. **Constraint:** Do not use substring comparisons; compare normalized path components and reject unresolved ambiguity.
43. **Decision:** Reject symlink destination directories for recursive operations. **Rationale:** A recursive write must not escape its configured root through a followed link. **Constraint:** `lstat` every destination ancestor from the configured root to the selected directory.

## Copy and move semantics

44. **Decision:** Preserve directory shape and file bytes only, matching current file copy; use default destination modes and current timestamps. **Rationale:** ROM operation correctness depends on content and names, not ownership metadata. **Constraint:** Do not promise metadata preservation in docs or UI.
45. **Decision:** For cross-filesystem Move, promote the complete staged destination first, then delete the verified source tree. **Rationale:** Interruption leaves at least one complete tree. **Constraint:** Source deletion begins only after final source verification and promotion.
46. **Decision:** If source deletion fails, retain both complete trees and report `copied, source not removed`; do not roll back the destination. **Rationale:** Removing a known-good destination after a deletion failure increases loss risk. **Constraint:** The operation is a failed move, so the clipboard remains.
47. **Decision:** Require the source tree to match the manifest immediately before promotion and again before deletion; any change prevents source deletion. **Rationale:** Never recursively remove files that were not copied. **Constraint:** Cleanup removes only manifest-matching entries bottom-up and refuses unexpected children.
48. **Decision:** Same-filesystem directory Move stays synchronous direct rename, with no worker/progress. **Rationale:** It is atomic and instant. **Constraint:** Only `:exdev` selects recursive work.
49. **Decision:** Keep regular-file copy/move synchronous and unchanged. **Rationale:** This issue should not destabilize proven file durability behavior. **Constraint:** The asynchronous command path dispatches only directory copy and `:exdev` directory move.
50. **Decision:** Stop at the first error and clean staging best-effort. **Rationale:** A complete-tree contract is simpler and safer than accumulating partial success. **Constraint:** Logs and result retain phase and relative path.

## Architecture and integration

51. **Decision:** Launcher owns the single active-job reference and Browser owns only serializable presentation state; a temporary `MayonnaiOS.Files.Worker` performs I/O under a dedicated DynamicSupervisor. **Rationale:** Launcher already owns input/browser state, while work must not run in it. **Constraint:** The worker is not registered globally; messages carry a unique job reference.
52. **Decision:** Add `MayonnaiOS.Files.Worker.sessions/0` to the application tree as a DynamicSupervisor and use temporary child specs. **Rationale:** This follows existing session supervision patterns and prevents automatic replay. **Constraint:** The supervisor exists on host and target for tests and development.
53. **Decision:** Every progress/result message includes the worker pid and opaque job reference; Launcher ignores nonmatching messages and monitors the pid. **Rationale:** Late messages cannot corrupt a later job. **Constraint:** `:DOWN` without a terminal result becomes a failure and clears active state.
54. **Decision:** Keep Browser pure. Add an operation presentation map (`phase`, counters, path, cancelling flag) to `Browser.t()`, while Launcher separately stores pid/ref and executes effects. **Rationale:** Scenes need progress data, not process handles. **Constraint:** Browser functions only transform data and return command data for paste/discard; they never spawn work.
55. **Decision:** Launcher sends a cooperative cancel message; Worker polls it at the checkpoints above, cleans staging, and returns cancelled. Forced termination is a last-resort crash path and is reported distinctly. **Rationale:** Killing a writer cannot guarantee cleanup. **Constraint:** B remains responsive because sending is nonblocking.
56. **Decision:** Put recursive scan/copy/move/cleanup mechanics in `MayonnaiOS.Files` behind location-based APIs and orchestration/progress/cancel polling in `MayonnaiOS.Files.Worker`. **Rationale:** Files remains the filesystem policy boundary; Worker owns process concerns. **Constraint:** No recursive public API accepts raw caller-supplied paths.
57. **Decision:** Keep injectable keyword seams for `df`/space, rename, sync, stat, progress clock, and cancellation; simulate `:exdev` as existing tests do. **Rationale:** Host tests cannot mount the target filesystems or observe real durability. **Constraint:** Production defaults always use the real filesystem functions.

## Acceptance and device validation

58. **Decision:** Host tests must cover nested and empty trees, zero/large files, byte fidelity/fsync ordering, final/stage no-overwrite, headroom ENOSPC, unknown space, nested symlink/special refusal, overlap, source mutation, cancellation at scan/copy, stale-stage discard validation, worker crash, and cross-filesystem move promotion/deletion ordering. **Rationale:** These are the data-loss boundaries. **Constraint:** Tests use real temporary trees plus narrow injected seams.
59. **Decision:** Browser/Launcher/scene tests must pin directory Copy availability, single-job gating, live navigation, B cancellation, blocked launch/sleep/poweroff/mutations, scanning/copying/cancelling footer text, stale-stage confirmation, terminal refresh, and user-facing errors. **Rationale:** Responsiveness and honest state are part of the feature, not decoration. **Constraint:** Tests remain headless and inspect Browser values/Scenic graph text.
60. **Decision:** Hardware acceptance must copy and move a representative nested ROM tree both directions between F2FS and exFAT; measure scan/progress/cancel responsiveness; test card removal; pull power during file copy and before promotion; reboot and verify only a marked `.part` tree remains; discard it on-device; and confirm same-filesystem directory move is instant. **Rationale:** Host tests cannot prove target filesystem behavior. **Constraint:** Use expendable test data and verify hashes before deleting source data.
61. **Decision:** Full `mix test` is the merge gate, with targeted `mix test test/files_test.exs test/browser_test.exs test/launcher_test.exs` after incremental work. **Rationale:** The feature crosses Files, Browser, Launcher, scene, and application supervision. **Constraint:** Hardware checks are additionally required before claiming device validation, but are not automated CI commands.
