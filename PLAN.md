# Implementation plan for #81: published documentation site

## Delivery sequencing

The implementation is intentionally delivered to `trunk` in two mergeable phases. Phase 1 publishes the generator, current retained pages, and the new site content while the README continues to use repository-relative `docs/*.md` links. After the first Pages deployment is confirmed at `https://kek.github.io/mayonnaios/`, Phase 2 reduces the README and changes its section links to the public site. This temporary duplication is expected and prevents a merged README from pointing at a site that has never deployed. Existing top-level Markdown files are rendered in place throughout, so their repository paths and initial public URLs never enter a broken intermediate state.

## Steps

1. **Add the isolated, pinned documentation toolchain.**
   - Create `.python-version` containing Python `3.13.7`.
   - Create root `pyproject.toml` as a docs-only Python project requiring exactly Python 3.13.7, MkDocs 1.6.1, and MkDocs Material 9.6.20; include only the narrowly required locked checker dependency if the checker cannot remain Python-standard-library-only.
   - Generate and commit `uv.lock`, including every transitive package; do not modify `mix.exs` or `mix.lock` and do not make any docs command invoke Mix.
   - Modify `.gitignore` to ignore `.venv/` and `site/` while continuing to track all source Markdown and docs assets.
   - Pin local and CI uv to 0.8.17. Document that lock refreshes are explicit dependency-update changes, while ordinary use is `uv sync --frozen`/`uv run --frozen`.
   - Validate from a clean checkout with uv 0.8.17: `uv sync --frozen`, then inspect the resolved versions with `uv tree`; confirm this succeeds without Elixir dependencies, SSH keys, WiFi variables, Docker, or target configuration.

   - Define explicit navigation, no more than three levels, in this order: Overview; Get started; User guides; Troubleshooting; Pickles; Development; Hardware status; Internals. Place the current `bluetooth-controller.md`, `data-layout.md`, and `retroarch-internals.md` files in that navigation without moving them. Keep `pickles.md` at the top level. Mark `retroarch-provisioning.md` as intentionally not in navigation but contextually reachable/searchable.
   - Exclude `docs/retroarch-reference/**` from page discovery and search while leaving the files in the repository. Configure strict validation for omitted pages, source-relative Markdown links, anchors, and root-absolute links so accidental `/...` internal links fail under the `/mayonnaios/` Pages subpath.
   - Create `docs/stylesheets/extra.css` only for minimal mobile safety: horizontally scrollable code/table containers, visible focus, and reduced-motion handling. Do not override Material contrast or navigation behavior.
   - Validate with a temporary minimal `docs/index.md` and all retained pages using `uv run --frozen mkdocs build --strict`; inspect generated links to confirm `/bluetooth-controller/`, `/data-layout/`, `/pickles/`, `/retroarch-internals/`, and `/retroarch-provisioning/` are produced exactly.

3. **Add a single strict repository/site checker before expanding content.**
   - Create `scripts/check_docs.py` with focused, deterministic checks for: every published Markdown page being either in explicit nav or an approved contextual-only list; repository-relative Markdown/source references resolving; generated internal URLs and fragments resolving; no root-absolute internal URL; asset paths resolving with exact case; PNGs being 640×480 and below 300 KB; generated output lacking common private-key/credential secret signatures; and the generated search index containing relevant pages for “add games,” “WiFi,” “Bluetooth,” “cores,” “Moonlight,” and “Pickles.”
   - Make the checker understand the Pages base path and validate generated `site/`, rather than issuing network requests for internal links. Keep known synthetic examples such as RFC1918 addresses allowed while failing actual key material patterns.
   - Create `docs/external-links-allowlist.txt` containing only reviewed transient or intentionally unavailable external URLs, with comments explaining each entry. Add a separate checker mode for retried external HTTP checks; external failures must report clearly but must not be part of the blocking local command.
   - Validate negative fixtures manually during implementation (missing fragment, case-mismatched image, unlisted page, oversized PNG, root-absolute link, key signature) and then remove those fixtures. Run the production sequence `uv run --frozen mkdocs build --strict` followed by `uv run --frozen python scripts/check_docs.py --site site` and require zero warnings/errors.
